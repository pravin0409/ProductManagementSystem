# Product Management System (WT Practical No. 07)

A full-stack web application designed to demonstrate interaction with a NoSQL database (MongoDB Atlas) through a Node.js and Express.js REST API, featuring a responsive Bootstrap 5 dashboard frontend.

---

## 1. Project Aim & Overview

- **Aim**: To design, develop, and deploy a web application that interacts with a NoSQL database (MongoDB Atlas) through a Node.js application.
- **Subject**: Web Technology (Practical No. 07)
- **Architecture**: Model-View-Controller (MVC) with clean separation between database models, business controllers, REST routes, and static frontend assets.

---

## 2. Technology Stack

- **Runtime**: Node.js
- **Backend Framework**: Express.js
- **Database**: MongoDB Atlas (Cloud NoSQL)
- **ODM (Object Data Modeling)**: Mongoose
- **Frontend**: HTML5, Vanilla JavaScript (ES6+ Fetch API)
- **UI Framework & Styling**: Bootstrap 5 (CDN), Bootstrap Icons (CDN), Custom CSS
- **Environment Management**: `dotenv`
- **Development Tool**: `nodemon`

## 4. Product Data Schema & Validation Rules

Each product document in the MongoDB collection contains the following fields:

| Field Name | Type | Required | Validation Rules | Description |
|---|---|:---:|---|---|
| `productName` | String | Yes | Trimmed, non-empty | Name of the product |
| `category` | String | Yes | Trimmed, non-empty | Product category (e.g., Electronics, Hardware) |
| `price` | Number | Yes | Min: `₹0.01` | Price in INR (must be greater than zero) |
| `quantity` | Number | Yes | Min: `0`, Integer | Available stock count (cannot be negative) |
| `description` | String | No | Trimmed, optional | Additional product details or specifications |
| `createdAt` | Date | Auto | Auto-generated by Mongoose | Timestamp of creation |
| `updatedAt` | Date | Auto | Auto-updated by Mongoose | Timestamp of last modification |

## 5. REST API Endpoints

All API endpoints are mounted under the `/api` prefix:

| Method | Endpoint | Description | Request Body | Success Status |
|---|---|---|---|:---:|
| `GET` | `/api/health` | Health check endpoint | None | `200 OK` |
| `GET` | `/api/products` | Retrieve all products (newest first) | None | `200 OK` |
| `POST` | `/api/products` | Create a new product record | JSON payload | `201 Created` |
| `GET` | `/api/products/:id` | Retrieve single product details by ID | None | `200 OK` |
| `PUT` | `/api/products/:id` | Update an existing product by ID | JSON payload | `200 OK` |
| `DELETE` | `/api/products/:id` | Delete a product record by ID | None | `200 OK` |

## 6. Local Setup Instructions (Windows)

### Prerequisites
- [Node.js](https://nodejs.org/) installed (v18 or higher recommended).
- A free [MongoDB Atlas](https://www.mongodb.com/cloud/atlas) account (or a local MongoDB instance).

### Step 1: Clone or Navigate to Project
```powershell
cd f:\College\TY\webtechnology\ProductManagementSystem
```

### Step 2: Install Dependencies
```powershell
npm install
```

### Step 3: Configure MongoDB Atlas & Environment Variables
1. Log in to [MongoDB Atlas](https://cloud.mongodb.com/).
2. Create or open your free M0 cluster.
3. Under **Security > Database Access**, create a database user with username and password.
4. Under **Security > Network Access**, click **Add IP Address** and select **Allow Access from Anywhere** (`0.0.0.0/0`) so cloud platforms and your local machine can connect.
5. In your cluster dashboard, click **Connect > Drivers**, copy the connection string, and substitute your username and password.
6. Open `.env` in the project root and set your connection URI:
   ```env
   PORT=5000
   MONGO_URI=mongodb+srv://<username>:<password>@cluster0.xxxxx.mongodb.net/product_db?retryWrites=true&w=majority
   ```

### Step 4: Run the Application
- **Development Mode (with auto-reload via nodemon)**:
  ```powershell
  npm run dev
  ```
- **Production Mode**:
  ```powershell
  npm start
  ```

### Step 5: Access the Dashboard
Open your web browser and navigate to:
```text
http://localhost:5000/
```

## 7. Viva & Practical Examination Reference

1. **Why use Mongoose over the native MongoDB driver?**
   - Mongoose provides structured schemas, automatic type casting, built-in validation rules, lifecycle hooks, and relationship management.
2. **How does error handling work?**
   - Controllers wrap async database calls in `try/catch` blocks.
   - Schema validation errors (`error.name === 'ValidationError'`) return HTTP `400` with user-friendly field messages.
   - Malformed MongoDB IDs (`!mongoose.Types.ObjectId.isValid(id)`) return HTTP `400`.
   - Missing documents return HTTP `404`.
   - Unhandled exceptions return HTTP `500` without leaking sensitive database credentials.
3. **How is security maintained?**
   - Connection credentials reside strictly in `.env`.
   - `.env` is listed in `.gitignore` to prevent leaking secrets to version control.
   - Frontend inputs are escaped to protect against Cross-Site Scripting (XSS).
4. **How are the summary cards computed?**
   - **Total Products**: Length of the live products array.
   - **Low Stock**: Filtered count where `quantity >= 1 && quantity <= 5`.
   - **Total Inventory Value**: JavaScript `reduce()` computing $\sum (\text{price} \times \text{quantity})$ formatted in INR (`₹`).
